# 体例管理功能优化方案

**日期**：2026-03-30
**版本**：v1.0
**状态**：待评审

---

## 一、需求背景

当前系统在生成教材内容时，仅支持简单的"写作风格"字段（如"教材"、"学术"等），无法精确控制生成内容的体例规范。用户希望能够：

1. 上传已有的体例文件（DOCX/PDF/TXT）
2. AI 自动分析体例特征（格式、结构、语言风格等）
3. 确认后保存为项目的体例模板
4. 后续生成内容时自动应用该体例规范

---

## 二、功能设计

### 2.1 核心流程

```
用户上传体例文件
  ↓
AI 分析体例特征（异步队列）
  ↓
展示分析结果（结构化展示）
  ↓
用户确认/修改
  ↓
保存为项目体例模板
  ↓
后续生成内容时自动应用
```

### 2.2 体例特征提取

AI 分析需要提取以下维度：

#### 2.2.1 结构特征
- 章节层级（如：章 → 节 → 小节）
- 标题格式（如：第一章、1.1、一、（一））
- 段落组织方式（如：总分总、并列式）

#### 2.2.2 格式规范
- 标题样式（字号、加粗、居中等）
- 正文格式（首行缩进、行距、字体）
- 列表格式（有序/无序、缩进规则）
- 引用格式（GB/T 7714、APA、MLA 等）

#### 2.2.3 语言风格
- 语气（正式/通俗、客观/主观）
- 人称（第一人称/第三人称）
- 术语密度（学术性强弱）
- 句式特点（长句/短句、主动/被动）

#### 2.2.4 内容特征
- 案例使用频率
- 图表使用规范
- 思考题/练习题格式
- 知识点标注方式（如：重点、难点、提示）

```typescript
// style-template.service.ts
async uploadAndAnalyze(file: Express.Multer.File, projectId: string) {
  // 1. 保存文件到 file 模块
  const uploadedFile = await this.fileService.upload(file, projectId);

  // 2. 创建 StyleTemplate 记录（status: analyzing）
  const template = await this.styleTemplateRepo.save({
    project_id: projectId,
    source_file_id: uploadedFile.id,
    status: 'analyzing',
    name: `体例分析-${new Date().toLocaleDateString()}`,
  });

  // 3. 加入 Bull 队列异步分析
  await this.styleAnalyzeQueue.add('analyze', {
    templateId: template.id,
    fileId: uploadedFile.id,
  });

  return template;
}
```

```typescript
export class StyleAnalyzer {

## 体例文件内容
${fileContent}

## 分析要求
请从以下维度提取体例特征，并以 JSON 格式输出：

1. **结构特征**：章节层级、标题格式
2. **格式规范**：标题样式、正文格式、引用格式
3. **语言风格**：语气、人称、术语密度
4. **内容特征**：案例频率、练习题格式

## 输出格式
\`\`\`json
{
  "structure": { ... },
  "format": { ... },
  "language": { ... },
  "content": { ... }
}
\`\`\``;

    const result = await this.agentService.generate({
      prompt,
      model: 'claude-sonnet-4-6',
    });

    return JSON.parse(result);
  }

- 章节格式：${features.structure.chapterFormat}
- 小节格式：${features.structure.sectionFormat}

### 格式规范
- 标题样式：${features.format.titleStyle}

- 术语密度：${features.language.termDensity}

### 内容要求
- 案例使用：${features.content.exampleFrequency}
- 练习题：${features.content.exerciseFormat}`;
  }
```

## 五、风险与挑战

### 5.1 AI 分析准确性

**风险**：AI 提取的体例特征可能不准确或不完整。

**应对**：
- 提供手动编辑功能，用户可修正 AI 分析结果
- 支持多次上传不同体例文件，AI 学习优化
- 提供体例模板库（预置常见出版社体例）

### 5.2 文件解析兼容性

**风险**：DOCX/PDF 文件格式复杂，解析可能失败。

**应对**：
- 复用现有 `file` 模块的解析器
- 对于复杂格式，提示用户转为纯文本上传
- 提供解析失败时的降级方案（手动输入体例规范）

### 5.3 Prompt 长度限制

**风险**：注入体例规范后，Prompt 可能超出模型上下文限制。

**应对**：
- 体例规范精简化，只保留核心要点
- 使用 Prompt 压缩技术（如：关键词提取）
- 支持分段生成（先生成结构，再填充内容）

### 7.2 数据库迁移脚本

```sql
-- 创建 style_templates 表
CREATE TABLE `style_templates` (
  `id` VARCHAR(36) PRIMARY KEY,
  `project_id` VARCHAR(36) NOT NULL,
  `name` VARCHAR(255) NOT NULL,
  `source_file_id` VARCHAR(36),
  `features` JSON NOT NULL,
  `prompt_template` TEXT NOT NULL,
  `is_active` BOOLEAN DEFAULT FALSE,
  `status` VARCHAR(20) DEFAULT 'draft',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (`project_id`) REFERENCES `projects`(`id`) ON DELETE CASCADE,
  FOREIGN KEY (`source_file_id`) REFERENCES `documents`(`id`) ON DELETE SET NULL
);

-- 为 projects 表添加 active_style_template_id 字段
ALTER TABLE `projects`
ADD COLUMN `active_style_template_id` VARCHAR(36),
ADD FOREIGN KEY (`active_style_template_id`) REFERENCES `style_templates`(`id`) ON DELETE SET NULL;

-- 创建索引
CREATE INDEX `idx_style_templates_project_id` ON `style_templates`(`project_id`);
CREATE INDEX `idx_style_templates_status` ON `style_templates`(`status`);
CREATE INDEX `idx_projects_active_style_template_id` ON `projects`(`active_style_template_id`);
```
