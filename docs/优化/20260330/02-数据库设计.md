# 体例管理功能 - 数据库设计文档

## 1. 表结构设计

### 1.1 新增表：style_templates

体例模板表，存储项目的体例模板及其特征配置。

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| id | varchar(36) | PRIMARY KEY | UUID | 主键 |
| project_id | varchar(36) | NOT NULL, FK | - | 所属项目 ID |
| name | varchar(255) | NOT NULL | - | 模板名称 |
| source_file_id | varchar(36) | NULL, FK | - | 关联的源文件 ID |
| features | json | NOT NULL | '{}' | 体例特征配置（JSON） |
| prompt_template | text | NOT NULL | '' | 生成时注入的 Prompt 模板 |
| is_active | boolean | NOT NULL | false | 是否为当前激活的体例 |
| status | varchar(20) | NOT NULL | 'draft' | 状态：draft/analyzing/ready/error |
| created_at | datetime | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | datetime | NOT NULL | CURRENT_TIMESTAMP | 更新时间 |

### 1.2 修改表：projects

在项目表中新增体例模板关联字段。

| 新增字段 | 数据类型 | 约束 | 默认值 | 说明 |
|---------|---------|------|--------|------|
| active_style_template_id | varchar(36) | NULL, FK | NULL | 当前激活的体例模板 ID |

## 2. 字段说明

### 2.1 style_templates 表字段详解

**id (varchar(36))**
- 使用 UUID 作为主键，避免 ID 冲突
- 使用 `uuid_generate_v4()` 自动生成

**project_id (varchar(36))**
- 关联到 projects 表，标识体例模板所属项目
- NOT NULL 约束，每个模板必须属于一个项目
- 外键关联，支持级联删除

**name (varchar(255))**
- 模板名称，用于用户识别和选择
- 限制 255 字符，满足常规命名需求
- NOT NULL 约束确保每个模板都有名称

**source_file_id (varchar(36))**
- 关联到 documents 表，标识体例分析的源文件
- 允许为空，模板可以手动创建而非从文件分析
- 外键关联，删除文件时设为 NULL

**features (json)**
- 存储体例特征的 JSON 配置
- 包含：语言风格、段落结构、引用规范、格式要求等
- 详细结构见优化方案第 3.1 节

**prompt_template (text)**
- 生成内容时注入的 Prompt 模板
- 由 AI 分析后自动生成，也可手动编辑
- 用于指导内容生成遵循体例规范

**is_active (boolean)**
- 标识是否为当前激活的体例模板
- 每个项目同时只能有一个激活的模板
- 默认 false

**status (varchar(20))**
- 模板状态：draft（草稿）、analyzing（分析中）、ready（就绪）、error（错误）
- 用于跟踪 AI 分析进度
- 默认 draft

**created_at / updated_at (datetime)**
- 记录模板创建和更新时间
- 用于排序和审计
- 自动维护时间戳

### 2.2 projects 表新增字段详解

**active_style_template_id (varchar(36))**
- 关联到 style_templates 表
- 允许为空，项目可以不使用体例模板
- 外键关联，支持级联查询
- 删除模板时，项目的该字段设为 NULL（不级联删除项目）

## 3. 索引设计

### 3.1 索引列表

| 表名 | 索引名 | 索引列 | 类型 | 说明 |
|------|--------|--------|------|------|
| style_templates | idx_style_templates_project_id | project_id | B-tree | 查询项目的所有模板 |
| style_templates | idx_style_templates_status | status | B-tree | 快速筛选不同状态的模板 |
| style_templates | idx_style_templates_is_active | is_active | B-tree | 快速查找激活的模板 |
| projects | idx_projects_active_style_template_id | active_style_template_id | B-tree | 查询使用某模板的项目 |

### 3.2 索引选择理由

**idx_style_templates_project_id**
- 高频查询：查询项目的所有体例模板
- 选择性高：每个项目的模板数量有限
- B-tree 索引适合等值查询和范围查询

**idx_style_templates_status**
- 常见场景：筛选不同状态的模板（如查找分析中的模板）
- 支持 `WHERE status = 'analyzing'` 快速查询
- 用于监控和管理模板分析任务

**idx_style_templates_is_active**
- 快速查找项目的激活模板
- 虽然选择性低（只有 true/false），但结合 project_id 查询时有效
- 支持 `WHERE project_id = ? AND is_active = true` 快速获取激活模板

**idx_projects_active_style_template_id**
- 查询使用某模板的所有项目
- 删除模板前检查是否有项目在使用
- 支持统计模板使用频率

### 3.3 性能优化考虑

1. **复合索引优化**：如果经常查询"某项目的激活模板"，可考虑创建 `(project_id, is_active)` 复合索引
2. **定期维护**：定期执行 `VACUUM` 和 `ANALYZE` 保持索引效率

## 4. 外键关系

### 4.1 外键列表

| 子表 | 子表字段 | 父表 | 父表字段 | 级联策略 | 说明 |
|------|---------|------|---------|---------|------|
| style_templates | project_id | projects | id | ON DELETE CASCADE | 删除项目时删除其体例模板 |
| style_templates | source_file_id | documents | id | ON DELETE SET NULL | 删除文件时模板字段设为 NULL |
| projects | active_style_template_id | style_templates | id | ON DELETE SET NULL | 删除模板时项目字段设为 NULL |

### 4.2 级联删除策略说明

**style_templates.project_id → projects.id (CASCADE)**
- 项目被删除时，其关联的所有体例模板也应删除
- 理由：体例模板是项目的附属资源，项目不存在则模板无意义

**style_templates.source_file_id → documents.id (SET NULL)**
- 删除源文件时，不删除体例模板
- 模板的 `source_file_id` 设为 NULL，模板继续存在
- 理由：体例模板已经分析完成，源文件删除不影响模板使用

**projects.active_style_template_id → style_templates.id (SET NULL)**
- 删除模板时，不删除使用该模板的项目
- 项目的 `active_style_template_id` 设为 NULL，项目继续存在
- 理由：项目是独立实体，删除模板不应影响已有项目
- 项目可以重新选择其他模板或不使用模板

### 4.3 ER 图（文字描述）

```
projects (1) ----< (N) style_templates
    |                      |
    | ON DELETE SET NULL   | ON DELETE SET NULL
    |                      |
    +----------------------+
           (激活关系)

documents (1) ----< (N) style_templates
                         (源文件关系)
```

关系说明：
- 一个项目可以有多个体例模板（1:N）
- 一个项目只能激活一个体例模板（N:1）
- 一个文件可以作为多个体例模板的源文件（1:N）

## 5. JSON 字段结构

### 5.1 features 字段 TypeScript 接口定义

参考优化方案第 3.1 节，`features` 字段存储体例特征配置：

```typescript
interface StyleFeatures {
  structure: {
    chapterFormat: string;    // 如："第{n}章"
    sectionFormat: string;    // 如："1.1"
    hierarchy: string[];      // 如：["章", "节", "小节"]
  };
  format: {
    titleStyle: string;       // 如："加粗、居中、二号字"
    paragraphIndent: boolean; // 是否首行缩进
    citationStyle: string;    // 如："GB/T 7714"
  };
  language: {
    tone: string;             // 如："正式、客观"
    person: string;           // 如："第三人称"
    termDensity: string;      // 如："中等"
  };
  content: {
    exampleFrequency: string; // 如："每节2-3个案例"
    exerciseFormat: string;   // 如："章末思考题"
  };
}
```

### 5.2 字段说明

**structure（结构特征）**
- 控制章节的组织方式和编号格式
- `chapterFormat`：章标题格式模板
- `sectionFormat`：节标题格式模板
- `hierarchy`：章节层级结构

**format（格式规范）**
- 控制文档的视觉呈现
- `titleStyle`：标题的样式描述
- `paragraphIndent`：是否使用首行缩进
- `citationStyle`：引用文献的格式标准

**language（语言风格）**
- 控制生成内容的语言表达方式
- `tone`：语气和情感色彩
- `person`：使用的人称
- `termDensity`：专业术语的使用程度

**content（内容特征）**
- 控制内容的组织和呈现
- `exampleFrequency`：案例使用频率
- `exerciseFormat`：练习题的格式和位置

### 5.3 示例 JSON 数据

```json
{
  "structure": {
    "chapterFormat": "第{n}章",
    "sectionFormat": "{chapter}.{section}",
    "hierarchy": ["章", "节", "小节"]
  },
  "format": {
    "titleStyle": "加粗、居中、二号字",
    "paragraphIndent": true,
    "citationStyle": "GB/T 7714"
  },
  "language": {
    "tone": "正式、客观",
    "person": "第三人称",
    "termDensity": "中等"
  },
  "content": {
    "exampleFrequency": "每节2-3个案例",
    "exerciseFormat": "章末思考题，每章5-8题"
  }
}
```

### 6.3 回滚方案

**完整回滚步骤**：
1. 执行 `npm run migration:revert` 自动回滚
2. 验证 `projects` 表的 `style_template_id` 字段已删除
3. 验证 `style_templates` 表已删除
4. 检查外键和索引是否清理干净

**数据保护**：
- 回滚前自动备份数据库：`pg_dump -U user -d dbname > backup.sql`
- 回滚操作不会删除 `projects` 表的其他数据
- `style_templates` 表数据会被删除，需提前导出：
  ```sql
  COPY style_templates TO '/tmp/style_templates_backup.csv' CSV HEADER;
  ```

**部分回滚**（仅删除字段，保留表）：
```sql
-- 仅删除 projects.style_template_id 字段
ALTER TABLE projects DROP COLUMN style_template_id;

-- 保留 style_templates 表供后续使用
```

## 7. 性能优化建议

### 7.1 查询优化

**常见查询模式**：
```sql
-- 1. 获取项目的所有模板（使用 idx_style_templates_project_id）
SELECT * FROM style_templates WHERE project_id = $1 ORDER BY created_at DESC;

-- 2. 获取项目的激活模板（使用 idx_style_templates_project_id + idx_style_templates_is_active）
SELECT * FROM style_templates WHERE project_id = $1 AND is_active = true;

-- 3. 获取分析中的模板（使用 idx_style_templates_status）
SELECT * FROM style_templates WHERE status = 'analyzing';

-- 4. 查询使用某模板的项目（使用 idx_projects_active_style_template_id）
SELECT * FROM projects WHERE active_style_template_id = $1;
```

### 7.2 缓存策略

**Redis 缓存**：
- 缓存项目的激活模板（TTL: 1 小时）
- 缓存模板详情（TTL: 1 小时）
- 缓存键格式：`style_template:{id}`, `project_active_template:{project_id}`

**缓存失效**：
- 创建/更新/删除模板时清除相关缓存
- 激活模板时清除项目的激活模板缓存

### 7.3 监控指标

**关键指标**：
- `style_templates` 表大小和增长速度
- 索引使用率（通过 `pg_stat_user_indexes` 查看）
- 慢查询日志（查询时间 > 100ms）
- 模板分析任务的平均耗时

**定期维护**：
```sql
-- 每周执行一次
VACUUM ANALYZE style_templates;
VACUUM ANALYZE projects;

-- 检查表大小
SELECT schemaname, tablename, pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) AS size
FROM pg_tables WHERE tablename IN ('style_templates', 'projects');
```
