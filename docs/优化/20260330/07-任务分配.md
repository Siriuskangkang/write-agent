## 5. 并行开发策略

### 5.1 后端并行开发

**后端 A**：
- 数据库设计 → Entity/DTO → Service → 集成

**后端 B**：
- Controller → Analyzer → Worker

**协作点**：
- Service 完成后，后端 B 开始 Controller
- Analyzer 需要调用 AgentService（已有）

### 5.2 前端并行开发

**前端 A**：
- 类型定义 → 路由配置 → 上传组件 → 分析状态组件 → 状态管理

**前端 B**：
- 预览组件 → 编辑组件 → 列表组件

**协作点**：
- 类型定义完成后，前端 B 可以开始组件开发
- 状态管理由前端 A 统一实现

### 5.3 前后端协作

**API 契约优先**：
- 后端先定义 API 接口（DTO）
- 前端根据接口定义开发
- 使用 Mock 数据进行前端开发

**联调时机**：
- 后端 Controller 完成后开始联调
- 前端组件完成后开始联调

## 6. 风险管理

### 6.1 技术风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| AI 分析不准确 | 高 | 中 | 提供手动编辑功能，支持多次分析 |
| 文件解析失败 | 中 | 低 | 复用现有解析器，提供降级方案 |
| SSE 连接不稳定 | 中 | 低 | 实现重连机制，提供轮询降级 |
| Prompt 过长 | 中 | 低 | 精简体例规范，使用关键词提取 |

### 6.2 进度风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 人员不足 | 高 | 中 | 调整优先级，砍掉 P2 功能 |
| 需求变更 | 中 | 中 | 冻结需求，变更走评审流程 |
| 测试时间不足 | 中 | 低 | 提前编写测试用例，并行测试 |

## 7. 沟通机制

### 7.1 日常沟通

- **每日站会**：15 分钟，同步进度和问题
- **技术讨论**：遇到技术难点时，拉群讨论
- **代码审查**：所有 PR 需至少 1 人 Review

### 7.2 文档协作

- **文档更新**：及时更新设计文档
- **API 文档**：使用 Swagger 自动生成
- **变更通知**：API 变更需通知前端

### 7.3 问题升级

- **技术问题**：先团队内讨论，无法解决时升级到项目负责人
- **进度问题**：及时上报，调整资源
- **需求问题**：走变更流程，评估影响
