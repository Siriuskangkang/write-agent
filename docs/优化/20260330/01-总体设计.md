# 体例管理功能总体设计文档

## 1. 需求概述

### 1.1 功能背景

当前教材编写系统支持用户上传素材文件并生成目录、大纲、正文，但生成的内容格式、风格、结构缺乏统一规范。不同用户、不同项目的输出结果差异较大，难以满足教材出版的标准化要求。

体例管理功能旨在为教材编写提供可复用的格式规范模板，用户可以：
- 上传已有教材作为体例参考
- 系统自动提取格式规范（章节结构、标题层级、段落格式、引用格式等）
- 在生成内容时应用体例规范，确保输出符合预期格式

### 1.2 核心目标

1. **格式标准化**：确保生成内容符合教材出版规范
2. **可复用性**：体例模板可跨项目复用
3. **智能提取**：AI 自动分析参考文档，提取格式规范
4. **灵活应用**：支持在生成目录/大纲/正文时选择性应用体例

### 1.3 功能范围

**包含功能**：
- 体例模板的创建、编辑、删除、查询
- 上传参考文档（DOCX/PDF/TXT）并解析
- AI 提取格式规范（章节结构、标题格式、段落格式、引用格式）
- 在生成内容时应用体例规范
- 体例模板的版本管理

**不包含功能**：
- 体例模板的导入/导出（后续版本）
- 体例模板的共享/市场（后续版本）
- 细粒度的格式编辑器（当前版本仅支持 AI 提取）

## 2. 功能目标

### 2.1 核心功能点

| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 体例模板 CRUD | 创建、查询、更新、删除体例模板 | P0 |
| 参考文档上传 | 支持 DOCX/PDF/TXT 格式上传 | P0 |
| AI 格式提取 | 自动分析参考文档，提取格式规范 | P0 |
| 体例应用 | 在生成内容时应用体例规范 | P0 |
| 体例预览 | 查看体例模板的详细内容 | P1 |
| 体例版本管理 | 记录体例模板的修改历史 | P2 |

### 2.2 功能边界说明

1. **格式提取范围**：
   - 章节结构（章/节/小节层级）
   - 标题格式（编号规则、字体大小、加粗等）
   - 段落格式（首行缩进、行距、对齐方式）
   - 引用格式（参考文献格式、脚注格式）
   - 列表格式（有序/无序列表样式）

2. **不支持的格式**：
   - 图片/表格的详细样式（仅提取结构）
   - 页眉/页脚/页码格式
   - 复杂的排版布局（多栏、文本框等）

3. **应用限制**：
   - 体例规范作为 AI 生成的约束条件，不保证 100% 严格遵守
   - 用户可在生成后手动调整格式

## 3. 用户流程

### 3.1 完整操作流程

```
1. 用户进入项目工作台
   ↓
2. 点击"体例管理"按钮，打开体例管理面板
   ↓
3. 创建新体例模板
   - 输入体例名称、描述
   - 上传参考文档（DOCX/PDF/TXT）
   ↓
4. 系统解析参考文档
   - 文件上传到服务器
   - Bull 队列异步解析文件内容
   - 解析完成后通知前端
   ↓
5. AI 提取格式规范
   - 用户点击"提取格式"按钮
   - 后端调用 Anthropic API 分析文档
   - SSE 流式返回提取结果
   - 前端展示提取的格式规范（JSON 结构）
   ↓
6. 用户确认并保存体例模板
   - 可手动编辑提取的格式规范
   - 保存到数据库
   ↓
7. 在生成内容时应用体例
   - 用户在生成目录/大纲/正文时选择体例模板
   - 后端将体例规范注入 AI prompt
   - 生成的内容符合体例格式
   ↓
8. 查看和管理体例模板
   - 查看体例列表
   - 编辑/删除体例模板
   - 查看体例应用历史
```

### 3.2 关键节点说明

- **文件解析节点**：复用现有 `file` 模块的解析逻辑，支持 PDF/DOCX/TXT
- **AI 提取节点**：使用 SSE 流式返回，用户可实时看到提取进度
- **体例应用节点**：在生成内容的 prompt 中注入体例规范，作为格式约束

### 4.2 技术栈选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端框架 | Next.js 14 (App Router) | 复用现有技术栈 |
| 状态管理 | Zustand | 新增 `styleStore` 管理体例状态 |
| UI 组件 | Ant Design | 复用现有组件库 |
| 后端框架 | NestJS | 新增 `StyleModule` |
| ORM | TypeORM | 新增 `StyleGuide`/`StyleFile`/`StyleVersion` 实体 |
| 数据库 | PostgreSQL | 复用现有数据库 |
| 队列 | Bull + Redis | 复用现有队列，新增 `style-extract` 队列 |
| AI 服务 | Anthropic Claude API | 复用现有 `AgentService` |
| 文件解析 | 复用 `file` 模块 | 支持 DOCX/PDF/TXT |

### 4.3 模块间交互说明

1. **前端 → 后端**：
   - 体例 CRUD：RESTful API（`/style-guide/*`）
   - 文件上传：`POST /style-guide/:id/upload`（multipart/form-data）
   - AI 提取：`POST /style-guide/:id/extract`（SSE 流式返回）

2. **后端 → 文件解析**：
   - 复用 `FileService.parseFile()` 方法
   - 解析结果不写入 `Document` 表，仅返回文本内容

3. **后端 → AI 服务**：
   - 调用 `AgentService.generateStream()`
   - 使用专用 prompt：`extract-style-guide.prompt.ts`
   - 返回 JSON 格式的格式规范

4. **后端 → 队列**：
   - 文件上传后入 `file-parse` 队列（复用现有）
   - AI 提取可选入 `style-extract` 队列（异步处理）

## 5. 模块划分

### 5.1 前端模块

#### 5.1.1 体例管理面板 (`StyleManagementPanel`)
- **路径**：`frontend/src/components/workbench/StyleManagementPanel.tsx`
- **功能**：
  - 展示体例模板列表
  - 创建/编辑/删除体例模板
  - 上传参考文档
  - 触发 AI 提取
  - 预览格式规范

#### 5.1.2 体例选择器 (`StyleSelector`)
- **路径**：`frontend/src/components/workbench/StyleSelector.tsx`
- **功能**：
  - 在生成内容时选择体例模板
  - 下拉选择或搜索
  - 显示体例预览

#### 5.1.3 格式预览组件 (`StylePreview`)
- **路径**：`frontend/src/components/workbench/StylePreview.tsx`
- **功能**：
  - 展示提取的格式规范（JSON 树形结构）
  - 支持折叠/展开
  - 高亮关键字段

#### 5.1.4 状态管理 (`styleStore`)
- **路径**：`frontend/src/stores/styleStore.ts`
- **状态**：
  - `styleGuides: StyleGuide[]` - 体例模板列表
  - `currentStyleGuide: StyleGuide | null` - 当前选中的体例
  - `extracting: boolean` - AI 提取中
  - `extractResult: string` - 提取结果（JSON 字符串）

### 5.2 后端模块

#### 5.2.1 StyleModule
- **路径**：`backend/src/style/style.module.ts`
- **依赖**：
  - `TypeOrmModule.forFeature([StyleGuide, StyleFile, StyleVersion])`
  - `FileModule`（复用文件解析）
  - `AgentModule`（AI 提取）
  - `BullModule.registerQueue({ name: 'style-extract' })`

#### 5.2.2 StyleController
- **路径**：`backend/src/style/style.controller.ts`
- **接口**：
  - `POST /style-guide` - 创建体例模板
  - `GET /style-guide` - 查询体例列表
  - `GET /style-guide/:id` - 查询单个体例
  - `PATCH /style-guide/:id` - 更新体例
  - `DELETE /style-guide/:id` - 删除体例
  - `POST /style-guide/:id/upload` - 上传参考文档
  - `POST /style-guide/:id/extract` - AI 提取格式（SSE）
  - `GET /style-guide/:id/versions` - 查询版本历史

#### 5.2.3 StyleService
- **路径**：`backend/src/style/style.service.ts`
- **方法**：
  - `create(dto: CreateStyleGuideDto): Promise<StyleGuide>`
  - `findAll(userId: number): Promise<StyleGuide[]>`
  - `findOne(id: number): Promise<StyleGuide>`
  - `update(id: number, dto: UpdateStyleGuideDto): Promise<StyleGuide>`
  - `remove(id: number): Promise<void>`
  - `uploadFile(id: number, file: Express.Multer.File): Promise<StyleFile>`
  - `extractStyle(id: number): AsyncGenerator<string>` - SSE 流式返回
  - `saveVersion(id: number, content: string): Promise<StyleVersion>`

#### 5.2.4 Prompt 文件
- **路径**：`backend/src/agent/prompts/extract-style-guide.prompt.ts`
- **内容**：
  - 分析参考文档，提取格式规范
  - 返回 JSON 结构：
    ```json
    {
      "chapterStructure": { "levels": 3, "numberingStyle": "1.1.1" },
      "titleFormat": { "level1": "bold, 18pt", "level2": "bold, 16pt" },
      "paragraphFormat": { "indent": "2em", "lineSpacing": "1.5" },
      "citationFormat": { "style": "APA", "example": "[1] Author. Title." },
      "listFormat": { "ordered": "1. 2. 3.", "unordered": "• - ◦" }
    }
    ```

### 5.3 数据库模块

#### 5.3.1 StyleGuide 实体
- **表名**：`style_guide`
- **字段**：
  - `id` (PK, auto-increment)
  - `name` (varchar, 体例名称)
  - `description` (text, 体例描述)
  - `user_id` (FK → user.id)
  - `project_id` (FK → project.id, nullable)
  - `format_spec` (jsonb, 格式规范 JSON)
  - `is_active` (boolean, 是否启用)
  - `created_at` (timestamp)
  - `updated_at` (timestamp)

#### 5.3.2 StyleFile 实体
- **表名**：`style_file`
- **字段**：
  - `id` (PK, auto-increment)
  - `style_guide_id` (FK → style_guide.id)
  - `file_name` (varchar)
  - `file_path` (varchar)
  - `file_size` (int)
  - `mime_type` (varchar)
  - `parsed_content` (text, 解析后的文本)
  - `created_at` (timestamp)

#### 5.3.3 StyleVersion 实体
- **表名**：`style_version`
- **字段**：
  - `id` (PK, auto-increment)
  - `style_guide_id` (FK → style_guide.id)
  - `version_number` (int)
  - `format_spec` (jsonb, 格式规范快照)
  - `change_summary` (text, 变更说明)
  - `created_by` (FK → user.id)
  - `created_at` (timestamp)

### 5.4 队列模块

#### 5.4.1 style-extract 队列
- **队列名**：`style-extract`
- **Worker**：`backend/src/style/workers/extract.worker.ts`
- **任务**：
  - 输入：`{ styleGuideId: number, fileId: number }`
  - 处理：调用 `AgentService.generateStream()` 提取格式
  - 输出：更新 `StyleGuide.format_spec` 字段
  - 错误处理：重试 3 次，失败后记录日志

## 6. 数据流设计

### 6.1 创建体例模板流程

```
用户输入体例名称/描述
  ↓
前端调用 POST /style-guide
  ↓
后端创建 StyleGuide 记录（format_spec 为空）
  ↓
返回体例 ID
  ↓
前端跳转到上传文件步骤
```

### 6.2 上传参考文档流程

```
用户选择文件（DOCX/PDF/TXT）
  ↓
前端调用 POST /style-guide/:id/upload
  ↓
后端保存文件到 uploads/style-files/
  ↓
创建 StyleFile 记录
  ↓
入队 file-parse（复用现有队列）
  ↓
Worker 解析文件内容
  ↓
更新 StyleFile.parsed_content
  ↓
通知前端解析完成
```

### 6.3 AI 提取格式流程

```
用户点击"提取格式"按钮
  ↓
前端调用 POST /style-guide/:id/extract（SSE）
  ↓
后端查询 StyleFile.parsed_content
  ↓
调用 AgentService.generateStream()
  - prompt: extract-style-guide.prompt.ts
  - input: parsed_content
  ↓
SSE 流式返回提取结果
  - event: meta（元数据）
  - event: token（逐 token 返回）
  - event: done（完整 JSON）
  ↓
前端展示提取结果
  ↓
用户确认后调用 PATCH /style-guide/:id
  ↓
后端更新 StyleGuide.format_spec
  ↓
创建 StyleVersion 记录（版本快照）
```

### 6.4 应用体例流程

```
用户在生成目录/大纲/正文时选择体例
  ↓
前端在请求中携带 styleGuideId
  ↓
后端查询 StyleGuide.format_spec
  ↓
将格式规范注入 AI prompt
  - 示例：
    "请按照以下格式规范生成内容：
     - 章节结构：3 级，编号格式 1.1.1
     - 标题格式：一级标题加粗 18pt，二级标题加粗 16pt
     - 段落格式：首行缩进 2em，行距 1.5
     - ..."
  ↓
调用 AgentService.generateStream()
  ↓
生成的内容符合体例格式
```

## 7. 安全与权限

### 7.1 权限控制

- **体例模板**：仅创建者可编辑/删除
- **项目级体例**：项目成员可查看，仅创建者可编辑
- **全局体例**：用户可创建个人全局体例，跨项目复用

### 7.2 文件安全

- **上传限制**：
  - 文件大小：最大 50MB
  - 文件类型：仅允许 DOCX/PDF/TXT
  - 文件名：过滤特殊字符，防止路径遍历
- **存储隔离**：
  - 体例文件存储在 `uploads/style-files/{userId}/{styleGuideId}/`
  - 与项目文件隔离

### 7.3 数据验证

- **格式规范 JSON**：
  - 后端验证 JSON 结构合法性
  - 前端展示前进行 schema 校验
  - 防止注入攻击

## 8. 性能优化

### 8.1 文件解析优化

- **复用现有解析器**：避免重复开发
- **异步队列**：大文件解析不阻塞主线程
- **缓存解析结果**：`StyleFile.parsed_content` 持久化

### 8.2 AI 提取优化

- **流式返回**：SSE 实时展示提取进度
- **超时控制**：AI 提取超过 60s 自动中断
- **重试机制**：失败后最多重试 3 次

### 8.3 数据库优化

- **索引**：
  - `style_guide.user_id`
  - `style_guide.project_id`
  - `style_file.style_guide_id`
  - `style_version.style_guide_id`
- **分页查询**：体例列表支持分页

## 11. 风险与挑战

### 11.1 技术风险

- **AI 提取准确性**：格式规范提取可能不准确，需人工校验
- **文件解析兼容性**：复杂 DOCX/PDF 可能解析失败
- **性能瓶颈**：大文件解析 + AI 提取耗时较长

### 11.2 应对措施

- **提供手动编辑**：AI 提取后允许用户手动调整
- **降级策略**：解析失败时提示用户上传纯文本
- **异步处理**：使用队列 + SSE，避免阻塞

---

## 12. 总结

体例管理功能通过 AI 自动提取参考文档的格式规范，为教材编写提供统一的格式约束。核心技术路线：

1. **文件解析**：复用现有 `file` 模块，支持 DOCX/PDF/TXT
2. **AI 提取**：调用 Anthropic API，流式返回格式规范 JSON
3. **体例应用**：在生成内容时将格式规范注入 prompt
4. **版本管理**：记录体例模板的修改历史

该功能与现有系统深度集成，复用文件解析、AI 服务、队列等基础设施，开发成本可控，预期 2-3 周完成核心功能。
