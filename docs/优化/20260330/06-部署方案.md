# 体例管理功能部署方案

## 1. 环境配置

### 1.1 环境变量清单

**后端环境变量**（`backend/.env`）

```bash
# 数据库配置
DATABASE_HOST=localhost
DATABASE_PORT=5432
DATABASE_USER=postgres
DATABASE_PASSWORD=your_password
DATABASE_NAME=write_agent

# Redis 配置
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=

# Anthropic API
ANTHROPIC_API_KEY=sk-ant-xxx
ANTHROPIC_BASE_URL=https://api.anthropic.com  # 可选
ANTHROPIC_MODEL=claude-sonnet-4-6

# OpenAI API（可选，用于 embedding）
OPENAI_API_KEY=sk-xxx

# JWT 配置
JWT_SECRET=your_jwt_secret
JWT_REFRESH_SECRET=your_refresh_secret

# 应用配置
FRONTEND_URL=http://localhost:8002
UPLOAD_DIR=./uploads
PORT=3002

# Bull 队列配置
BULL_BOARD_USERNAME=admin
BULL_BOARD_PASSWORD=admin
```

**前端环境变量**（`frontend/.env.local`）

```bash
NEXT_PUBLIC_API_URL=http://localhost:3002
```

### 1.2 依赖服务检查

部署前确认以下服务运行正常：

```bash
# 检查 PostgreSQL
psql -h localhost -U postgres -c "SELECT version();"

# 检查 Redis
redis-cli ping

# 检查 Node.js 版本
node --version  # 需要 >= 18.x

# 检查 npm 版本
npm --version
```

## 2. 数据库迁移

### 2.1 备份现有数据

```bash
# 进入项目目录
cd /Users/kang/Desktop/write-agent

# 创建备份目录
mkdir -p backup

# 备份数据库
pg_dump -h localhost -U postgres -d write_agent \
  > backup/pre_style_template_$(date +%Y%m%d_%H%M%S).sql

# 验证备份文件
ls -lh backup/
```

```bash

cd backend

# 安装依赖（如有更新）
npm install

# 运行迁移
npm run migration:run

# 验证迁移结果
npm run migration:show
```

## 3. 服务部署

### 3.1 后端部署步骤

```bash
# 1. 进入后端目录
cd backend

# 2. 安装依赖
npm ci --production=false

# 3. 运行测试
npm run test
npm run test:e2e

# 4. 构建
npm run build

# 5. 验证构建产物
ls -lh dist/

# 6. 重启后端服务
pm2 restart write-agent-backend

# 7. 查看日志
pm2 logs write-agent-backend --lines 50
```

### 3.2 前端构建部署

```bash
# 1. 进入前端目录
cd frontend

# 2. 安装依赖
npm ci

# 3. 类型检查
npm run typecheck

# 4. 构建
npm run build

# 5. 验证构建产物
ls -lh .next/

# 6. 重启前端服务
pm2 restart write-agent-frontend

# 7. 查看日志
pm2 logs write-agent-frontend --lines 50
```

### 3.3 PM2 配置更新

**文件位置**：`ecosystem.config.cjs`

确认配置包含以下内容：

```javascript
module.exports = {
  apps: [
    {
      name: 'write-agent-backend',
      cwd: './backend',
      script: 'dist/main.js',
      instances: 1,
      exec_mode: 'fork',
      env: {
        NODE_ENV: 'production',
        PORT: 3002
      },
      error_file: './logs/backend-error.log',
      out_file: './logs/backend-out.log',
      log_date_format: 'YYYY-MM-DD HH:mm:ss'
    },
    {
      name: 'write-agent-frontend',
      cwd: './frontend',
      script: 'node_modules/next/dist/bin/next',
      args: 'start -p 8002',
      instances: 1,
      exec_mode: 'fork',
      env: {
        NODE_ENV: 'production',
        PORT: 8002
      },
      error_file: './logs/frontend-error.log',
      out_file: './logs/frontend-out.log',
      log_date_format: 'YYYY-MM-DD HH:mm:ss'
    }
  ]
};
```

重启所有服务：

```bash
pm2 restart ecosystem.config.cjs
pm2 save
```

## 5. 回滚方案

### 5.1 回滚步骤

如果部署后发现严重问题，按以下步骤回滚：

**步骤 1：停止服务**

```bash
pm2 stop write-agent-backend
pm2 stop write-agent-frontend
```

**步骤 2：回滚代码**

```bash
# 查看最近的提交
git log --oneline -5

# 回滚到上一个稳定版本
git revert <commit-hash>

# 或者硬回滚（谨慎使用）
git reset --hard <stable-commit-hash>
```

**步骤 3：回滚数据库**

```bash
# 恢复备份
psql -h localhost -U postgres -d write_agent \
  < backup/pre_style_template_YYYYMMDD_HHMMSS.sql

# 或者运行回滚迁移
cd backend
npm run migration:revert
```

**步骤 4：重新构建**

```bash
# 后端
cd backend
npm ci
npm run build

# 前端
cd frontend
npm ci
npm run build
```

**步骤 5：重启服务**

```bash
pm2 restart ecosystem.config.cjs
pm2 logs --lines 100
```

### 5.2 数据恢复

**完整恢复**

```bash
# 删除现有数据库
dropdb -h localhost -U postgres write_agent

# 重新创建
createdb -h localhost -U postgres write_agent

# 恢复备份
psql -h localhost -U postgres -d write_agent \
  < backup/pre_style_template_YYYYMMDD_HHMMSS.sql
```

**部分恢复**（仅恢复体例模板表）

```sql
-- 连接数据库
psql -h localhost -U postgres -d write_agent

-- 删除新表
DROP TABLE IF EXISTS style_template CASCADE;

-- 从备份中恢复（需要先导出单表）
\i backup/style_template_only.sql
```

## 6. 监控与告警

### 6.1 日志监控

```bash
# 实时查看所有日志
pm2 logs

# 查看错误日志
pm2 logs --err

# 查看特定服务日志
pm2 logs write-agent-backend

# 保存日志到文件
pm2 logs --raw > deployment.log
```

### 6.2 关键指标监控

**服务健康**

- PM2 进程状态
- CPU 使用率 < 80%
- 内存使用率 < 80%
- 磁盘使用率 < 80%

**数据库监控**

```sql
-- 连接数
SELECT count(*) FROM pg_stat_activity;

-- 慢查询
SELECT query, calls, total_time, mean_time
FROM pg_stat_statements
ORDER BY mean_time DESC
LIMIT 10;

-- 表大小
SELECT
  schemaname,
  tablename,
  pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) AS size
FROM pg_tables
WHERE schemaname = 'public'
ORDER BY pg_total_relation_size(schemaname||'.'||tablename) DESC;
```

**队列监控**

- 待处理任务数 < 100
- 失败任务数 = 0
- 平均处理时间 < 30s

### 6.3 告警配置

建议配置以下告警：

- 服务宕机告警
- CPU/内存使用率超过 80%
- 数据库连接数超过阈值
- 队列任务失败率 > 5%
- API 响应时间 > 3s
- 磁盘空间不足
