# 体例驱动生成改造计划

> 问题：体例分析结果正确，但目录/大纲/正文生成时完全没有遵循体例。

## 根本原因

`getStylePrompt()` 引用了旧的字段（`features.structure.chapterFormat` 等），但新体例 JSON 结构已改为 `hierarchy / columns / figures` 等，导致注入的体例信息全为空。

即使修复字段映射，目录生成的 prompt 要求输出 `chapters/sections` 两层结构，而体例定义的是**模块→项目→任务**三层，格式上根本不匹配。

---

## 改动范围

| 层 | 文件 | 改什么 |
|---|---|---|
| 体例注入 | `content.service.ts: getStylePrompt()` | 字段映射改为新结构 |
| 目录 prompt | `agent/prompts/directory.prompt.ts` | 输出结构支持三层（模块/项目/任务） |
| 目录解析 | `content.service.ts: parseDirectory()` | 解析新的三层 JSON |
| 目录前端树 | `DirectoryTree` 组件 | 渲染三层节点 |
| 大纲 prompt | `agent/prompts/outline.prompt.ts` | 输出结构改为体例栏目列表 |
| 大纲解析 | `content.service.ts: parseOutline()` | 解析新的栏目结构 |
| 正文 prompt | `agent/prompts/content.prompt.ts` | 按栏目顺序写正文 |

---

## 实施顺序

**第一步：修复 `getStylePrompt()`**
优先级最高，其他所有改动都依赖它。把旧字段映射改为新结构，验证体例确实注入进去了。

**第二步：改目录（prompt + 解析 + 前端）**
三个文件需要联动修改，目录结构变化影响后续所有流程。

**第三步：改大纲（prompt + 解析）**
依赖目录的节点信息，目录改完再改。

**第四步：改正文 prompt**
依赖大纲结构，大纲改完再改。

---

## 关键决策：目录结构兼容性

新的目录 JSON 结构有两个选项：

**方案 A：强制三层（模块/项目/任务）**
- 有体例时生成三层结构
- 无体例时回退到原来的章/节两层
- 前端需要区分两种模式渲染

**方案 B：通用节点树（推荐）**
- 统一用 `nodes` 数组，每个节点有 `level` 字段标注层级类型
- 前端统一渲染，无需区分模式
- 扩展性更好
