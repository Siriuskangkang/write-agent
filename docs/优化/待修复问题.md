### BUG-03 目录结构中素材支撑度标签无意义

**描述**：目录树每个节点旁边会显示 `充足` / `一般` / `不足` 的彩色 Tag，用户不理解其含义，也不知道有什么用。

**影响**：用户看到"不足"标签时，不知道这是"素材支撑度不足"的意思，也不知道该如何应对。

**优先级**：中

**相关模块**：`frontend/src/components/workbench/DirectorySidebar.tsx` → `NodeTitle` 组件

**根因**：后端 prompt 要求 AI 对每个小节评估素材支撑度（充足/一般/不足），前端直接把枚举值原文渲染为 Tag，没有任何说明或 tooltip。

**修复方案**：
1. 给 Tag 加 `Tooltip`，悬停时显示说明，例如："素材支撑度：该小节在已上传素材中的参考内容较少"。
2. 或将 Tag 文字改为更易懂的表达：`充足` → `素材充足`，`不足` → `素材不足`。
3. 可选：在目录树顶部加一行小字说明"颜色标签表示该节的素材支撑度"。

### BUG-04 素材管理文件名中文乱码

**描述**：上传含中文名的文件后，素材管理列表中文件名显示乱码（如 `????.pdf`）。

**影响**：对用户不友好，无法识别已上传的文件。

**优先级**：高

**相关模块**：`backend/src/file/file.service.ts:70`

**根因**：multer 默认使用 `latin1` 解码文件名，中文 UTF-8 字节流被误读后直接持久化到数据库。

**修复方案**：在 `file.service.ts` 的 `uploadFiles` 方法中，对 `file.originalname` 做 latin1 → UTF-8 转码：

```typescript
const originalName = Buffer.from(file.originalname, 'latin1').toString('utf8');
```

将 `file_name: file.originalname` 改为 `file_name: originalName`，`safeName` 同步修改。

### BUG-05 素材未被感知用于生成 / 大量文件支持能力不足

**描述**：用户上传了素材，但不清楚素材是否真的被用于生成目录；另外上传大量文件（几十个）时存在限制。

**优先级**：中

**相关模块**：`backend/src/content/content.service.ts`、`frontend/src/app/projects/[id]/materials/page.tsx`、`backend/src/file/file.controller.ts`

#### 5.1 素材是否真的被用于生成？

**现状**：素材确实有被使用——后端会做关键词检索，把 top 10 chunks 拼入 prompt。但有一个前提：文件必须解析完成（`parse_status = done`）。如果用户刚上传完就立刻点"生成目录"，文件还在解析队列中，检索结果为空，AI 等于没有素材。前端没有任何提示。

**修复方案**：前端在工作台检查是否有文件处于 `pending`/`parsing` 状态，若有则提示："部分素材仍在解析中，建议等待解析完成后再生成，以获得更好效果。"

#### 5.2 大量文件支持

| 环节 | 当前限制 | 问题 |
|------|----------|------|
| 上传接口 | 单次最多 20 个文件 | 几十个文件需要分批上传，体验差 |
| 素材列表 | 前端 `page_size: 100` 写死 | 超过 100 个文件时无法查看全部 |
| 检索 | `top_k: 10` 固定 | 文件越多，参考比例越低（可接受） |

**修复方案**：
1. 后端 `FilesInterceptor` 单次上传上限从 20 提升到 50。
2. 前端素材列表改为支持分页，不写死 `page_size: 100`。
3. 素材管理页面增加说明："已上传素材将在解析完成后自动用于内容生成"。

### BUG-06 没有登出功能

**描述**：前端没有任何登出入口，用户无法主动退出登录。

**影响**：用户无法切换账号，也无法在公共设备上安全退出。

**优先级**：高

**相关模块**：前端 - 导航/用户菜单

**现状**：后端已有完整的 `POST /api/auth/logout` 接口（`auth.controller.ts:71`），会清除 cookie 并使 refresh token 失效，但前端没有任何地方调用它，也没有登出按钮。

**修复方案**：在前端导航栏或用户头像下拉菜单中添加"退出登录"按钮，点击后调用 `POST /api/auth/logout`，成功后清空本地 Zustand 状态并跳转到登录页。

### BUG-08 素材管理上传第二个文件出现重复条目

**描述**：在素材管理页面，上传第一个文件正常；上传第二个文件后，列表中出现两条相同的记录。

**影响**：用户看到重复文件，困惑是否真的上传了两份。

**优先级**：高

**相关模块**：`frontend/src/app/projects/[id]/materials/page.tsx`

**根因分析**：`onChange` 回调在 Ant Design Upload 组件中会对 fileList 中每个文件的状态变化都触发一次。`beforeUpload: () => false` 阻止了自动上传，但 `onChange` 仍会在每次 fileList 变化时触发（包括添加文件、移除文件等），导致多次调用 `uploadFiles` 并多次 `fetchFiles()`，或者 fileList 累积了历史文件导致重复上传。

**修复方案**：改用 `customRequest` 或在 `onChange` 中只在 `status === 'done'` / 所有文件都 ready 时触发一次上传，避免重复触发。

### BUG-13 更新目录名称时报 scrollTo 空指针

**描述**：第一次修改目录节点名称时，前端抛出运行时错误。

```
TypeError: Cannot read properties of null (reading 'scrollTo')
Call Stack: Tree.scrollTo → Tree.onActiveChange → onFocus
node_modules/@rc-component/tree/es/Tree.js
```

**影响**：编辑目录名称时页面报错，用户体验中断。

**优先级**：高

**相关模块**：`frontend/src/components/workbench/DirectorySidebar.tsx`

**修复方案**：在调用 `scrollTo` 前判断 ref 是否存在，或升级 `@rc-component/tree` 到已修复该问题的版本。

### FEAT-04 目录 / 大纲 / 正文强关联生成

**描述**：三者生成目前缺乏严格的上下文约束，可能出现对不上的情况。

**优先级**：高

**相关模块**：`backend/src/agent/prompts/`、`backend/src/content/content.service.ts`

**期望行为**：
- 目录：根据教材设置信息（课程名称、受众、章节数等）生成，章节数与设置一致
- 大纲：严格按目录结构生成，每章的小节数量与目录中的小节一一对应
- 正文：以当前章节的目录条目 + 对应大纲作为上下文参考生成，不得超出范围

**修复方案**：在各生成 prompt 中注入上一级结构数据作为约束，后端在调用链中传递目录/大纲上下文。
