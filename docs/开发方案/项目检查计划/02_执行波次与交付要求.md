# 执行波次与交付要求

## 波次总览

本项目建议分 5 个执行波次推进，不建议跳波次。

| 波次 | 模块 | 主责任AI | 目标 |
|---|---|---|---|
| `W0` | 准备阶段 | `A0` | 建立模块状态表、确认当前基线、分派任务 |
| `W1` | `M01` `M02` `M03` | `A1` | 先让工程、认证、项目基础资源稳定 |
| `W2` | `M04` `M05` `M06` `M07` | `A2` | 打通素材到检索的基础数据链路 |
| `W3` | `M08` `M09` `M10` `M11` `M12` `M13` | `A3` | 打通生成、引用、会话、导出主业务链路 |
| `W4` | `M14` | `A4` | 补齐页面和工作台集成，使主流程可被真实用户使用 |
| `W5` | `M15` | `V1` | 进行全链路、边界、异常、并发和真实场景验收 |

## 每一波的进入条件

### `W0`

- 已有最新代码
- 已有开发文档
- 已知当前构建状态

### `W1`

- `A0` 已确认当前环境变量、构建状态、分支状态

### `W2`

- `W1` 已完成
- 登录态、项目、基础 API 可用

### `W3`

- `W2` 已完成
- 素材上传、解析、切块、检索结果可稳定回读

### `W4`

- `W3` 已完成
- 后端主链路接口已稳定

### `W5`

- `W1` 到 `W4` 均已至少完成主检查和最小自检

## 每一波的结束条件

### `W1` 结束条件

- 前后端构建通过，或者阻塞项被明确记录
- 认证主链路可用
- 项目 CRUD 与项目状态接口可用
- `V1` 已完成本波黑盒验证

### `W2` 结束条件

- 至少一种素材格式可完整从上传走到 `documents/chunks`
- 各解析器输出结构已确认
- 向量文档拆分规则与字段落盘规则已确认
- 检索结果字段完整，基础关键词召回可用
- `V1` 已完成本波黑盒验证

### `W3` 结束条件

- 目录、大纲、正文、引用、会话、导出主链路至少各完成一轮闭环
- 数据能从生成写入，再从接口回读
- 中断、失败、重复操作的状态行为已明确
- `V1` 已完成本波黑盒验证

### `W4` 结束条件

- 页面缺口补齐
- 工作台、素材页、引用面板、导出流程与后端保持一致
- 刷新页面和重新进入项目后状态恢复合理
- `V1` 已完成本波黑盒验证

### `W5` 结束条件

- 覆盖所有主流程、边界场景、异常场景、并发场景
- 形成正式验收报告
- 所有未通过项都有明确归属模块和责任AI

## 单模块交付格式

每个模块完成时必须交付以下内容：

### 主检查AI交付

- 本模块当前问题列表
- 根因分析
- 修改文件清单
- 修改说明
- 最小自检结果
- 剩余风险

### 黑盒验证AI交付

- 验证标准
- 执行步骤
- 正向结果
- 边界结果
- 负项结果
- 证据
- 最终结论

## 不允许的推进方式

- 未完成 `W1` 就开始大规模前端页面补齐
- 未确认切块与检索链路前，就判断目录/正文生成质量
- 只修 happy path，不做边界和失败场景
- 只看代码，不实际运行验证
- 把一个强耦合模块拆成“分析AI、修复AI、测试AI”流水线

## 模块状态标记建议

| 状态 | 含义 |
|---|---|
| `not_started` | 未开始 |
| `in_progress` | 主检查AI处理中 |
| `self_checked` | 主检查AI已完成最小自检 |
| `pending_verification` | 等待 `V1` 黑盒验证 |
| `verified` | 已通过黑盒验证 |
| `blocked` | 被上游模块或环境阻塞 |
| `failed_verification` | 已修复但未通过黑盒验证 |
