# 教材编写Agent 测试报告

测试日期：2026-03-18

## 1. 测试目标

基于 `开发文档/项目检查计划/` 下的检查计划，对当前项目进行一轮分模块测试，输出可用于后续修复和复测的正式报告。

本轮重点覆盖：

- `M01` 到 `M14` 的工程基线、接口契约、素材处理、生成链路、前端工作台集成
- 构建、现有自动化测试、关键代码路径审查
- 边界场景和真实使用场景的实现缺口识别

本轮未完成：

- 依赖完整运行环境的真实联调
- 真实浏览器级 E2E 回归
- 数据库、Redis、队列和样本数据支撑下的全链路动态验证

## 2. 测试组织方式

本轮采用多代理协同测试。

- 主线程：汇总基线测试、执行构建和自动化测试、整合最终报告
- 子代理 `gpt-5.4` x 3：
  - 工程/认证/项目专项
  - 素材解析/切块/向量化/检索专项
  - 前端工作台/流式交互/会话/引用/导出专项

## 4. 总体结论

当前项目不能判定为“可验收”。

更准确地说：

- 工程层面：前端和后端构建已基本可跑，但自动化测试基线不成立
- 数据层面：素材已能进入 `documents/chunks`，但“向量文档链路”尚未闭环
- 业务层面：目录、正文、引用、会话、导出、设置等关键链路存在明显闭环缺口
- 前端层面：页面可构建，但工作台状态恢复、会话持久化、大纲展示、引用回读仍未真正接通

阶段判断：

- `W1` 未通过
- `W2` 未通过
- `W3` 未通过
- `W4` 未通过
- `W5` 暂不具备开始条件

## 5. 高优先级发现

以下问题会直接阻塞验收或造成高风险错误行为。

### 5.1 测试基线与工程能力

1. 后端 e2e 测试当前不可用。`npm run test:e2e -- --runInBand` 直接失败，原因是 ts-jest 环境无法解析 `AppModule` 中的 `.js` 扩展导入。
涉及模块：`M01`

2. 前端测试基线不存在。`frontend/package.json` 中 `npm test` 仍是固定失败的占位脚本。
涉及模块：`M01`

3. 后端单测虽能通过，但仍然只有默认 `Hello World` 示例测试，不覆盖任何实际业务链路。
涉及模块：`M01`

### 5.2 认证、项目和设置能力

4. 项目设置和个人设置能力未落地，但已在计划中作为系统能力要求；当前缺少 `/projects/[id]/settings`、`/settings` 页面和对应后端实现。
涉及模块：`M03` `M14`

5. 项目状态只有读路径，没有前端写路径。后端已有 `PUT /projects/:id/state`，但前端没有接入，目录版本、完成章节、用户备注等无法持久化。
涉及模块：`M03` `M14`

6. 前后端密码规则不一致。前端注册页要求至少 8 位，而后端注册和改密 DTO 仍是至少 6 位。
涉及模块：`M02`

### 5.3 资源隔离与权限控制

7. 文件、切块、检索等资源接口缺少项目归属校验，存在跨项目读写风险。当前多个控制器只做“已登录”校验，没有对用户与项目归属做收口。
涉及模块：`M04` `M06` `M07`

### 5.4 素材处理与向量文档链路

8. 向量文档链路未真正闭环。`ChunkService` 将 `embedding` 固定写为 `null`，`RetrievalService.getQueryEmbedding()` 也固定返回 `null`，语义检索实际上未启用。
涉及模块：`M06` `M07`

9. `embedding` 的实体定义与 migration 不一致。migration 定义为 `vector(1536)`，实体定义却是 `float[]`，后续即使补 embedding 生成也会有高概率写入或查询异常。
涉及模块：`M06` `M07`

10. `ParseWorker` 在创建 chunk 之前就把文件状态更新为 `DONE`，会产生“显示解析完成但 chunk 未落库”的假完成状态。
涉及模块：`M04` `M06`

11. 文件重解析和删除在已有引用后很可能失败。当前删除 `chunks/documents` 时没有同步清理 `citation_maps`，而数据库外键没有 `ON DELETE CASCADE`。
涉及模块：`M04` `M06`

12. 检索关键词分支存在实现缺陷。`search_terms` 查询使用了带 `%` 的参数，导致数组匹配路径基本失效。
涉及模块：`M07`

### 5.5 生成链路、会话和工作台

13. 会话持久化未接入前端工作台。前端没有实际调用 `sessions` 接口，聊天消息写入时 `session_id` 为空字符串，刷新后上下文无法恢复。
涉及模块：`M12` `M14`

14. 大纲链路在前端没有独立闭环。大纲生成结果会被当成正文结果处理，`currentOutline` 基本未被使用。
涉及模块：`M09` `M10` `M14`

15. 目录生成依赖前端解析 AI 返回的 JSON，并固定以 `base_version_number: 1` 保存，目录版本链和失败恢复都很脆弱。
涉及模块：`M08` `M14`

16. 引用面板只消费内存里的 SSE 引用，未接入后端引用回读接口，刷新页面后引用必然丢失。
涉及模块：`M11` `M14`

## 6. 中优先级发现

1. `useSSE` 直接拼接 `NEXT_PUBLIC_API_URL`，绕过同源 `/api` 访问约束和 Next rewrite。
涉及模块：`M08` `M09` `M10` `M14`

2. 停止生成只做前端 `abort()`，没有执行“中止后重新请求结果状态”的恢复策略。
涉及模块：`M10` `M14`

3. 前端 `SSEEvent` 和 `useSSE` 都没有 `heartbeat` 处理，和计划要求不一致。
涉及模块：`M08` `M09` `M10`

4. 素材切块规则没有 overlap，且在 `TXT/Markdown` 轻量样本下已经出现明显过碎 chunk。
涉及模块：`M06`

5. 解析器 section 质量不稳定。PDF 按页切、DOCX 启发式猜标题、TXT 按空行成段，教材场景下容易碎片化或误判。
涉及模块：`M05` `M06`

6. 上传接口缺少显式文件类型和大小校验，非法格式更可能在数据库约束或解析阶段暴露。
涉及模块：`M04`

7. 工作台和导航里没有项目设置入口，真实使用流程不完整。
涉及模块：`M14`

## 7. 低优先级发现

1. 素材页前端接受 `.doc`，但当前文档契约和后端支持列表是 `docx`。
涉及模块：`M04` `M14`

2. 项目列表虽然做了最近编辑排序，但因为缺少项目设置和编辑入口，实际价值有限。
涉及模块：`M03`

## 11. 向量文档链路专项结论

关于“上传的素材怎么正确拆分成向量文档”，本轮测试结论如下：

当前状态：

- 已实现：`source_files -> documents -> chunks -> 关键词检索`
- 未实现闭环：`embedding 生成 -> embedding 入库一致性 -> query embedding -> 语义召回 -> 混合检索`

因此，当前项目还不能说“素材已经正确拆分成向量文档”，最多只能说：

`素材已经进入了检索文档切块阶段，但尚未完成真正的向量化闭环。`

正确的闭环标准应至少包括：

1. 解析器稳定产出 `Document.sections`
2. `chunk` 长度和边界合理，不明显过碎
3. `chunk` metadata 完整
4. `embedding` 真实生成并入库
5. `embedding` 类型与数据库一致
6. 检索能回溯到文件、页码、section
7. 重解析后旧数据能被正确清理

## 12. 结论摘要

当前项目离“可验收的教材编写 Agent”还有明显距离。

最关键的事实有三点：

1. 自动化测试基线尚未建立，工程验收标准不足
2. 素材到向量检索的链路尚未闭环
3. 工作台核心闭环还缺少会话持久化、大纲独立状态、引用回读、设置页和中止恢复

这意味着下一步不应该直接做终验，而应先按模块修复，再逐轮复测。
