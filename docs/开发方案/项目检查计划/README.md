# 教材编写Agent 检查计划目录

这个目录用于替代单文件的粗检查计划，作为后续多 AI 协同检查与修正的主入口。

旧文件 `开发文档/教材编写Agent_项目检查计划.md` 可以保留作为背景材料，但后续执行应以本目录为准。

## 总体拆分

- 总检查模块数：15
- AI 角色数：6
- 组织方式：按上下文和系统边界拆分，不按“产品/开发/测试”流水线拆分

## AI 角色

| 角色 | 代号 | 主要职责 |
|---|---|---|
| 总控AI | `A0` | 维护检查计划、依赖顺序、完成状态和跨模块收口标准 |
| 工程契约AI | `A1` | 工程基线、配置、认证、接口契约、项目基础能力 |
| 数据处理AI | `A2` | 文件上传、解析、切块、向量化、检索与数据库一致性 |
| 生成链路AI | `A3` | 目录、大纲、正文、引用、会话、导出等生成主链路 |
| 前端集成AI | `A4` | 页面、路由、状态管理、工作台交互、前后端联调 |
| 黑盒验证AI | `V1` | 构建、接口、链路、异常、边界、真实场景回归验证 |

## 文档清单

- `01_模块清单与AI分工.md`
  说明一共有多少模块、每个模块由谁主检、谁协同、谁验证、交付什么。
- `02_执行波次与交付要求.md`
  说明按什么顺序推进、每一波的进入条件和结束条件是什么。
- `03_素材解析与向量文档拆分专项.md`
  专门说明上传素材如何被正确解析、切块、生成检索文档和向量数据。
- `04_真实场景与边界矩阵.md`
  列出必须覆盖的真实使用场景、异常场景、并发场景和边界情况。

## 使用规则

1. 每次只启动一个主检查模块，不并行改多个强耦合模块。
2. 每个模块由一个主检查AI负责到底，必要时拉一个协同AI，不做流水线式拆分。
3. 每个模块完成后，都要交给 `V1` 做黑盒验证。
4. 任何模块未通过黑盒验证，不得标记为完成。
5. 涉及素材解析、切块、向量化、检索的改动，必须同时参考 `03_素材解析与向量文档拆分专项.md`。
